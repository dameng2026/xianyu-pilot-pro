## 一、用户管理页面现状

### 1.1 页面定位

后台用户管理路由 `/system/user`，权限 `R_SUPER`/`R_ADMIN`，组件 `apps/admin-web/src/views/system/user/index.vue`。

调用链路：
```
admin-web (Vue3)
  → /admin-api/admin/users (列表) + /admin-api/admin/modules/users (CRUD)
  → AdminModuleController → AdminModuleService.pageUsers()
  → SysUserService (JdbcTemplate 直接操作 sys_user 表)
  → /admin-api/system/user/{id}/{reset-password,token-balance,vip-level} (专用端点)
  → SysUserController → SysUserService
```

## 二、存在的问题（按严重程度分级）

### P0 - 严重 Bug（必须修复）

#### Bug 1：编辑用户时 PII 脱敏数据被写回数据库（数据损坏）

**问题**：列表接口 `pageUsers` 对 phone/email 做了脱敏（如 `138****1234`）。编辑弹窗 `initForm` 直接从列表行数据回填表单。当管理员点击"编辑"→不修改 phone/email→点击"确定"时，**脱敏后的字符串 `138****1234` 会被当作真实手机号保存到数据库**。

**位置**：[user-dialog.vue](file:///g:/源码/xianyu-assistant-package-temp/apps/admin-web/src/views/system/user/modules/user-dialog.vue) `initForm` 方法

**根因**：
- `fetchGetUserDetail` API 已定义但从未被调用
- 即便调用，后端 `SysUserController.detail` 也做了脱敏（`maskPii`），详情接口本身不返回原始数据
- `sysUserService.update` 不重新校验 phone/email 格式，脱敏值直接入库

**影响**：被编辑过的用户 phone/email 全部被破坏为带星号字符串，导致短信通知、密码找回等功能失效。

#### Bug 2：表格出现两个"序号"列

**位置**：[index.vue](file:///g:/源码/xianyu-assistant-package-temp/apps/admin-web/src/views/system/user/index.vue) 列定义中存在两个 `{ type: 'index' }` 列

**影响**：UI 视觉冗余，第二个序号列无表头标签。

#### Bug 3：编辑时三次独立 API 调用无事务保护

**位置**：[user-dialog.vue](file:///g:/源码/xianyu-assistant-package-temp/apps/admin-web/src/views/system/user/modules/user-dialog.vue) `handleSubmit`

```typescript
await fetchUpdateUser(id, payload)              // 1. 更新基本信息
await fetchUpdateUserVipLevel(id, form.vipLevel)      // 2. 更新 VIP
await fetchUpdateUserTokenBalance(id, form.tokenBalance) // 3. 更新 Token
```

**影响**：若第 1 步成功、第 2 步失败，用户基本信息已变更但 VIP 未变更，数据状态不一致。三个接口各自独立 `@Transactional`，跨接口无事务。

#### Bug 4：批量启用/禁用无二次确认

**位置**：[index.vue](file:///g:/源码/xianyu-assistant-package-temp/apps/admin-web/src/views/system/user/index.vue) `handleBatchEnable` / `handleBatchDisable`

**对比**：`handleBatchDelete` 和单个状态切换 `handleToggleStatus` 都有 `ElMessageBox.confirm`，唯独批量启禁用直接执行，**确认机制不一致**，误操作风险高。

### P1 - 重要问题

#### 问题 1：列表接口未返回 tokenBalance，但表格有该列

**问题**：前端列表用的是 `AdminModuleService.pageUsers`（有 `xianyuAccountCount` 无 `tokenBalance`），但表格同时显示两列 —— **tokenBalance 列会显示为空/undefined**。

只有 `enrichUserLevels` 填充 VIP 等级，没有填充 tokenBalance。

#### 问题 2：重置密码功能完全不可用

**问题**：
- 后端 `SysUserController.resetPassword` 已完整实现（含 6 位长度校验、用户存在性校验、BCrypt 加密）
- 前端 `fetchResetUserPassword` API 已定义
- **但 UI 完全没有重置密码入口**，编辑模式下密码字段被隐藏

**影响**：管理员无法重置用户密码，用户忘记密码只能自行通过短信验证码找回。

#### 问题 3：双控制器职责重叠，8 个端点完全闲置

`AdminModuleController`（`/admin-api/admin/*`）和 `SysUserController`（`/admin-api/system/user/*`）都实现了用户的 page/detail/create/update/delete/batch-delete/status/batch-status。

`SysUserController` 的这 8 个端点**完全闲置**（前端只用其 reset-password/token-balance/vip-level 三个），造成：
- 代码重复（两套分页查询逻辑，字段映射略不同）
- 维护负担（改一处可能漏改另一处）
- 字段不一致：`pageUsers` 返回 `xianyuAccountCount`，`SysUserService.page` 不返回

#### 问题 4：VIP 等级来源混乱

`enrichUserLevels` 有两套 VIP 来源：
1. `sys_user.vip_level`（手动覆盖，优先级高）
2. `billing_subscription` + `billing_plan`（订阅来源）

弹窗只能编辑 `vip_level`，但表格显示的可能是订阅来源的等级。更严重的是：**前台 `UserProfileService.queryActivePlan()` 只读 `billing_subscription`，不读 `vip_level`**。

**影响**：后台手动调整 `vip_level` 后，前台个人中心不会显示该等级，前后台数据不一致。

#### 问题 5：编辑时无法修改密码

**问题**：编辑模式下密码字段被隐藏（`v-if="dialogType === 'add'"`），且重置密码 API 未接入。

**影响**：管理员只能通过未接入的重置密码接口修改密码，实际无法操作。

#### 问题 6：租户 ID 是纯文本输入

**位置**：[user-dialog.vue](file:///g:/源码/xianyu-assistant-package-temp/apps/admin-web/src/views/system/user/modules/user-dialog.vue)

**问题**：`tenantId` 是纯文本输入框，管理员必须手动输入数字 ID，不知道有哪些租户可选。

### P2 - 改进型问题

#### 问题 7：动态 DDL（运行时改表结构）

**位置**：`SysUserService.ensureVipLevelColumn()`

每次 `updateVipLevel` 和 `enrichUserLevels` 时检查 `vip_level` 列是否存在，不存在则 `ALTER TABLE` 添加。生产环境运行时改表结构是高风险反模式：
- 多实例并发时可能冲突
- 应通过 Flyway/Liquibase 迁移工具管理 schema
- 异常被 `catch (Exception ignored)` 吞掉，可能导致 vip_level 永久失效

#### 问题 8：Avatar 字段未使用

**问题**：`sys_user.avatar` 字段存在，但：
- 列表 `ElAvatar` 仅显示 `UserFilled` 默认图标，未使用 `row.avatar`
- 编辑弹窗无头像上传组件
- 前台用户也无头像上传入口

#### 问题 9：搜索字段名不符

**位置**：[user-search.vue](file:///g:/源码/xianyu-assistant-package-temp/apps/admin-web/src/views/system/user/modules/user-search.vue) + system-manage.ts

**问题**：搜索字段名 `username` 实际传到后端被映射成 `keyword`，模糊匹配 4 个字段（username/nickname/phone/email）。字段名语义与实际行为不符。

#### 问题 10：操作未写入审计日志

**问题**：`sysUserService` 仅 `log.info` 写日志文件，未写入 `operation_log` 表。项目有 `OperationAuditService` 但用户管理操作未接入。

**影响**：用户删除、状态变更、密码重置等高风险操作无法追溯操作人。

#### 问题 11：选中状态跨页不保留

**位置**：[index.vue](file:///g:/源码/xianyu-assistant-package-temp/apps/admin-web/src/views/system/user/index.vue) `handleSelectionChange`

**问题**：翻页后选中清空，`selectedIds` 仅在批量操作后清空，翻页时未处理，无法跨页批量操作。

#### 问题 12：状态字段类型混乱

**问题**：全链路 status 在字符串"正常"/"禁用"和数字 1/0 之间反复转换：
- 搜索栏下拉值是中文字符串
- 表单内部用字符串
- 提交时转数字
- 后端 `parseStatusCode` 还接受"异常"/"true"/"false"等多种变体

类型定义 `UserFormData.status: number` 与实际表单状态不符，国际化困难。

#### 问题 13：类型定义冗余字段

**位置**：[api.d.ts](file:///g:/源码/xianyu-assistant-package-temp/apps/admin-web/src/types/api/api.d.ts) `UserListItem`

包含 `userName`/`nickName`/`userPhone`/`userEmail`/`userGender` 等"旧版 demo 兼容字段"，实际后端不返回，应清理。

## 三、前后台功能对比分析

### 3.1 字段管理能力对比

| 字段 | 前台用户自助 | 后台管理员 | 差距 |
|------|------------|----------|------|
| username | 不可改 | 可改 | - |
| password | 修改（需原密码） | **重置功能未接入** | 后台缺失 |
| nickname | **无入口** | 可改 | 前台缺失 |
| phone | 修改（需验证码） | 可改（无验证码） | - |
| email | 修改（需验证码） | 可改（无验证码） | - |
| avatar | **无入口** | **字段未使用** | 双方都缺失 |
| tenant_id | 不可改 | 可改（纯文本输入） | 体验差 |
| status | 不可改 | 可改 | - |
| token_balance | 仅充值（增加） | 可直接调整 | - |
| vip_level | 不可改 | 可改 | **前台不读此字段** |
| phone_verified/email_verified | 仅自助验证置位 | **不可改** | 后台缺失 |
| 会员订阅 | 通过支付激活 | **无管理入口** | 后台缺失 |

### 3.2 前后台数据不一致问题

#### 问题 A：VIP 等级双重来源不一致

- 后台 `enrichUserLevels`：`sys_user.vip_level` 优先，否则读 `billing_subscription`
- 前台 `UserProfileService.queryActivePlan()`：只读 `billing_subscription`，**不读 `vip_level`**

**结果**：后台手动调整 `vip_level` 后，前台个人中心不显示该等级。

#### 问题 B：Python 侧遗留接口是安全后门

`apps/automation-service/app/api/v1/routes/login.py` 仍可实现：
- `POST /login/register`（无短信验证码、无手机号校验、无租户创建，密码 6-50 位）
- `POST /login/login`（无密码强度升级、无租户）

虽然前端 baseURL 指向 Java，但 Python 侧 `/automation/api/v1/login/*` 路由仍可被直接访问，**可绕过 Java 侧所有安全策略创建无租户用户**。

#### 问题 C：Python 侧 SysUser 实体字段过时

Python `SysUser` 实体仅 10 个基础字段，缺少：
- `avatar`、`last_login_time`、`last_login_ip`、`token_balance`
- `phone_verified`、`email_verified`、`last_security_update_time`、`vip_level`

若未来 Python 侧需要读写这些字段，需先更新实体定义。

#### 问题 D：验证码存储不一致

- 注册/登录验证码：Redis（`xya:sms:code:{target}`，5分钟 TTL，重启不丢失）
- 个人中心修改手机/邮箱验证码：Java 内存 `ConcurrentHashMap`（`codeStore`，5分钟 TTL，**重启丢失**）

### 3.3 后台缺失的前台能力管理

| 前台能力 | 后台管理入口 | 说明 |
|---------|------------|------|
| 会员订阅管理 | ✗ | 无法直接给用户开通/关闭订阅，只能通过支付订单回调 |
| Token 流水查看 | ✗ | 无法查看用户 Token 充值/消费明细 |
| 支付订单查看 | ✗ | 无法查看用户支付记录 |
| 登录历史 | ✗ | 仅显示 lastLoginTime/lastLoginIp，无历史记录 |
| 通知设置查看 | ✗ | 无法查看用户配置的通知渠道 |
| 操作日志关联 | ✗ | 无法查看某用户的操作历史 |

## 四、优化建议

### 4.1 P0 必须修复

#### 修复 1：解决 PII 脱敏数据写回问题

**方案 A（推荐）**：编辑弹窗中 phone/email 字段显示为脱敏值，但提交时：
- 若字段未修改（与脱敏值相同），不传该字段
- 若字段已修改（与脱敏值不同），传新值并校验格式

**方案 B**：新增"未脱敏详情"接口（仅超管可调用），编辑前调用获取原始数据。

**方案 C**：编辑弹窗中 phone/email 显示为占位符 `********`，留空表示不修改。

#### 修复 2：删除重复的序号列

删除 [index.vue](file:///g:/源码/xianyu-assistant-package-temp/apps/admin-web/src/views/system/user/index.vue) 中第二个 `{ type: 'index', width: 60 }` 列定义。

#### 修复 3：合并编辑时的三次 API 调用

**方案**：新增后端统一更新接口 `PUT /admin-api/admin/modules/users/{id}`，在单个事务中更新基本信息 + VIP + Token。

或扩展现有 `update` 方法接收 `vipLevel` 和 `tokenBalance` 参数，在同一个 `@Transactional` 内完成。

#### 修复 4：批量启用/禁用增加二次确认

```typescript
const handleBatchEnable = async () => {
  await ElMessageBox.confirm(
    `确认启用选中的 ${selectedIds.value.length} 个用户？`,
    '批量启用确认',
    { type: 'warning' }
  )
  // ... 执行
}
```

### 4.2 P1 重要优化

#### 优化 1：接入重置密码功能

- 在行操作菜单和编辑弹窗中增加"重置密码"入口
- 重置时弹窗输入新密码（或生成随机密码并显示）
- 调用已实现的 `fetchResetUserPassword` API
- 增加密码强度策略（至少 8 位，含字母+数字）

#### 优化 2：列表接口补齐 tokenBalance 字段

在 `AdminModuleService.pageUsers` 的 SQL 中增加 `token_balance` 字段，或在 `enrichUserLevels` 中一并填充。

#### 优化 3：统一 VIP 等级来源

**方案**：
- 前台 `UserProfileService.queryActivePlan()` 也读取 `sys_user.vip_level`，与后台保持一致
- 或废弃 `sys_user.vip_level` 字段，统一通过 `billing_subscription` 管理
- 后台增加"会员订阅管理"入口，可直接给用户开通/关闭订阅

#### 优化 4：清理双控制器重复端点

- 删除 `SysUserController` 中闲置的 8 个端点（page/detail/create/update/delete/batch-delete/status/batch-status）
- 仅保留 reset-password / token-balance / vip-level 三个专用端点
- 或将这三个端点也合并到 `AdminModuleController`，彻底消除 `SysUserController`

#### 优化 5：租户 ID 改为下拉选择器

- 新增租户列表接口 `GET /admin-api/admin/tenants`
- 编辑弹窗中 tenantId 改为 `ElSelect`，显示租户名称，值为租户 ID
- 支持搜索和分页

#### 优化 6：编辑模式增加修改密码入口

- 编辑弹窗增加"修改密码"折叠区域（可选填）
- 留空表示不修改，填写则调用重置密码接口

### 4.3 P2 改进型优化

#### 优化 7：移除动态 DDL

- 通过 Flyway 迁移脚本添加 `vip_level` 字段
- 删除 `SysUserService.ensureVipLevelColumn()` 方法
- 缓存 `vip_level` 列存在性检查结果（若保留检查）

#### 优化 8：接入操作审计日志

在 `SysUserService` 的 create/update/delete/batchDelete/updateStatus/resetPassword/updateTokenBalance/updateVipLevel 方法中调用 `OperationAuditService` 记录操作：
- 操作人（从 `AdminContext` 获取）
- 操作类型（CREATE/UPDATE/DELETE/RESET_PASSWORD 等）
- 目标用户 ID
- 操作详情（JSON）
- 操作时间

#### 优化 9：Avatar 字段使用

- 列表 `ElAvatar` 使用 `row.avatar`，无头像时显示默认图标
- 编辑弹窗增加头像上传组件（复用 `AdminAvatarController` 上传逻辑）
- 前台 `ProfileCenterPage.vue` 也增加头像上传入口

#### 优化 10：搜索字段名修正

- `user-search.vue` 中字段名改为 `keyword`，placeholder 改为"用户名/昵称/手机号/邮箱"
- 或保持 `username` 但后端参数名也统一为 `username`，明确语义

#### 优化 11：跨页选中保留

- 使用 `row-key` 指定主键
- 使用 `ElTable` 的 `reserve-selection` 属性
- 翻页时保留选中状态

#### 优化 12：状态字段统一为数字

- 搜索栏下拉值改为 `1`/`0`，label 显示"正常"/"禁用"
- 表单内部状态用数字
- 后端统一接收数字，移除 `parseStatusCode` 的多变体支持

#### 优化 13：清理类型定义冗余字段

删除 [api.d.ts](file:///g:/源码/xianyu-assistant-package-temp/apps/admin-web/src/types/api/api.d.ts) `UserListItem` 中的 `userName`/`nickName`/`userPhone`/`userEmail`/`userGender` 等未使用字段。

### 4.4 新增功能建议

#### 新增 1：用户详情页

当前编辑弹窗信息有限，建议新增用户详情页（抽屉或独立页），展示：
- 基本信息（用户名、昵称、手机、邮箱、头像、注册时间）
- 会员信息（当前订阅、VIP 等级、到期时间）
- Token 信息（余额、今日消耗、七日消耗、流水明细链接）
- 业务统计（闲鱼账号数、商品数、订单数、会话数）
- 登录历史（最近 10 次登录时间/IP）
- 操作日志（该用户的操作历史）

#### 新增 2：会员订阅管理

后台增加"会员订阅管理"入口：
- 查看用户当前订阅
- 手动开通/续费/关闭订阅
- 调整订阅有效期
- 记录操作日志

#### 新增 3：Token 流水查看

后台用户列表行操作增加"Token 流水"入口：
- 查看用户 Token 充值/消费明细
- 支持时间范围筛选
- 显示今日/七日/总计消耗统计

#### 新增 4：支付订单查看

后台用户列表行操作增加"支付订单"入口：
- 查看用户支付订单列表
- 订单状态、金额、支付方式、时间
- 支持手动标记支付成功（沙箱场景）

## 六、安全风险专项

### 6.1 高风险问题

| 风险 | 说明 | 建议 |
|------|------|------|
| Python 侧 login.py 是安全后门 | 可绕过 Java 侧所有安全策略创建无租户用户 | 禁用 Python 侧 `/login/*` 路由，或加 IP 白名单限制仅内部调用 |
| PII 脱敏数据写回数据库 | 编辑用户后 phone/email 被破坏 | P0 修复（见 4.1） |
| 重置密码无二次身份验证 | 管理员可重置任意用户密码 | 增加管理员密码二次确认或操作日志审计 |
| reset-password 密码强度策略弱 | 仅校验 `length >= 6` | 要求至少 8 位，含字母+数字 |
| 批量删除无审计 | 无法追溯操作人 | 接入 OperationAuditService |
| 验证码存内存 | 重启 Java 服务丢失个人中心验证码 | 迁移到 Redis |

### 6.2 PII 保护建议

当前后台 phone/email 全部脱敏，管理员无法看到完整信息。但某些场景需要完整信息（如客服核对、手动修改）：

**建议方案**：
- 新增"查看完整 PII"权限（仅 R_SUPER）
- 详情页增加"显示完整手机号"按钮，点击后记录审计日志
- 或保持现状，通过 username/userId 定位用户，不依赖完整 PII

## 七、总结

后台用户管理页面**核心 CRUD 功能可用**，但存在以下关键问题：

1. **数据安全 Bug（P0）**：编辑用户时 PII 脱敏数据被写回数据库，会破坏用户 phone/email
2. **功能缺失**：重置密码功能后端已实现但前端未接入；编辑时无法修改密码；会员订阅无法管理
3. **前后台不一致**：VIP 等级来源不一致；前台无头像/昵称修改入口；Python 侧遗留接口是安全后门
4. **架构冗余**：双控制器重复实现 8 个端点；动态 DDL 反模式；类型定义冗余字段
5. **体验问题**：重复序号列；Token 列显示空；租户 ID 纯文本输入；批量启禁用无确认；跨页选中不保留

建议按 P0 → P1 → P2 三阶段实施，**第一阶段必须修复 PII 数据写回 Bug**，避免用户数据持续被破坏。第二阶段接入重置密码、统一 VIP 来源、清理重复端点。第三阶段新增用户详情页、会员订阅管理、Token 流水查看等增强功能。
