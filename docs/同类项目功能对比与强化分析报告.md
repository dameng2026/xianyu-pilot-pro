## 三、同类项目更完善/更强大的差异点（详细）

### 3.1 自动回复：关键词规则管理

同类项目 `frontend/src/pages/keywords/Keywords.tsx` 提供完整的桌面管理页：

- 文本关键词：多行保存、重复校验、按账号/商品筛选、分页、批量删除。
- 图片关键词：上传图片、支持关联多个商品、图片预览、优先级高于文本关键词。
- 商品绑定：新增时多选商品批量生成规则；编辑时单选商品；支持“通用关键词”。
- 导入导出：Excel 导出、Excel 导入（含商品 ID 归一化）。
- 回复变量：`{send_user_name}`、`{send_user_id}`、`{send_message}`。
- 多消息拆分：`######` 分隔多条消息依次发送。
- 回复内容留空 = 命中但屏蔽（可做黑名单效果）。

我方 `apps/automation-service/app/models/entities.py` 已有 `auto_reply_rule` 表（支持 keyword/ai/all/regex/exact、优先级、账号作用域），运行时匹配函数 `_match_auto_reply_rule`（`automation_runtime.py:7226`）能力不弱，但：

- 桌面端没有规则管理页面（只有移动端 `MobileAutomation.vue` 的简化列表）。
- 后端 `auto_reply.py` 只提供 list/save/delete，缺少 update/status toggle/分页/统计。
- 没有图片关键词、商品绑定、Excel 导入导出、变量说明等体验能力。

### 3.2 自动回复：默认回复

同类项目 `backend-web/app/api/routes/default_replies.py` + `default_reply_service.py`：

- 按账号配置默认回复：启用开关、回复类型（text / api）、文本内容、回复图片、API 地址与超时（防 SSRF 校验）、`reply_once` 仅回复一次。
- 未命中关键词且 AI 未启用时兜底使用默认回复。

我方在 `process_incoming_message`（`automation_runtime.py:5525`）中：未命中规则 → 尝试 AI 客服 → 未启用则直接返回“未命中自动回复规则，且 AI 客服未启用”，没有任何兜底回复能力。

### 3.3 消息过滤规则

同类项目 `backend-web/app/api/routes/message_filters.py` + 前端 `MessageFilters.tsx`：

- 按账号配置关键词过滤规则，过滤类型：`skip_reply`（不自动回复）、`skip_notify`（不推送通知）。
- 支持单条/批量创建、批量删除、启停切换、重复校验。

我方完全没有该能力：任何买家消息都会进入自动回复链路，且 `ws_client.py:2065` 对所有新消息广播，用户无法按关键词屏蔽骚扰/广告消息。

### 3.4 自动发货：执行顺序与风控

同类项目 `websocket/app/services/xianyu/auto_delivery_handler.py`：

- `is_confirm_before_send_enabled()`：先确认发货成功再发卡券，失败则不发送。
- `is_send_before_confirm_enabled()`：先发卡券并等待平台回执（如 CSI_FORBID）再确认发货。
- 禁止发货规则引擎 `delivery_rules/`：买家信用、已有订单、未确认收货、个人/平台黑名单；支持规则优先级与排除商品；拦截后可写 `delivery_fail_reason` 并可选关单。
- `card_only`：订单已关闭但开关开启时仅补发卡券。

我方 `ws_delivery_handler.py` 的实时发货流程为“先发送内容 → 再 `_auto_confirm_shipment`”，没有“先确认再发送”选项；也没有买家维度发货拦截规则（只有重复发货防抖与订单状态防线）。

## 四、强化方案与优先级

按“交叉功能、用户价值、实施可控性”排序：

| 优先级 | 强化项 | 对应差异 | 实施范围 |
|--------|--------|----------|----------|
| P0 | 消息过滤规则（跳过自动回复 / 跳过通知） | 3.3 | automation-service 表+CRUD+运行时；core-api 代理；user-web 页面 |
| P0 | 默认回复（文本/API/仅回复一次） | 3.2 | automation-service 表+CRUD+运行时；core-api 代理；user-web 设置页 |
| P1 | 自动回复规则桌面管理页 | 3.1 | 后端补齐 update/toggle/分页；user-web 新页面与菜单 |
| P2 | 自动发货“先确认后发卡”顺序开关 | 3.4 | 发货配置 + `ws_delivery_handler` 分支 + AutoDeliveryPage 配置 |

> 说明：同类项目的“禁止发货规则引擎”“商品监控”“共享扫码”“卡券对接”属于独立能力或与我方现有架构差异过大，本期不移植；其中规则引擎的“黑名单”能力可后续基于本报告的账号/订单数据补充。

## 五、验收口径

1. 消息过滤：配置规则后，命中关键词的消息不再触发自动回复；`skip_notify` 命中消息不再向在线消息页广播新消息。
2. 默认回复：未命中关键词且 AI 客服关闭时，按账号发送默认回复；API 类型调用外部接口并正确超时；`reply_once` 只回复一次。
3. 规则管理页：可增删改查、启停、按账号筛选，变量提示清晰。
4. 发货顺序开关：开启后先确认发货，失败则不发送卡券内容。
5. 以上功能全部通过本地构建/测试，并部署到线上后做冒烟验证。
