## 第一部分：总览

### 1.1 背景与目标

将商业版（功能完整版）的 7 项功能同步到开源版（`xianyu-assistant-opensource`）：

| 序号 | 功能 | 所属任务包 |
|------|------|-----------|
| 1 | 商品管理页面 改价/编辑 | A |
| 2 | 编辑商品页面 + 发布商品页面的多规格发布 | A |
| 3 | 评价管理页面（修复刷新/同步/自动评价不可用） | B |
| 4 | 自动发货页面 + 货源库页面：多规格自动发货配置 | B |
| 5 | 货源库新增货源：图片发货 + 多正文发货配置 | B |
| 6 | 在线消息页面/自动发货页面等相关逻辑 | B |
| 7 | 滑块求解功能（轨迹模拟/重试/反检测，**不含 x5sec**） | C |

### 1.2 两个项目架构对比（重要，决定同步方式）

| 维度 | 商业版 | 开源版 |
|------|--------|--------|
| 后端 | Java core-api（网关/本地DB）+ Python automation-service（闲鱼业务） | 纯 Python `apps/api`（单服务，前端直连） |
| 爬虫/浏览器 | `apps/crawler-service`（TS + Python sliderSolve.py + x5secCache.ts + 代理池） | `apps/crawler`（仅 3 个 TS 文件：server.ts / sliderSolver.ts / fileSecret.ts） |
| 前端 | `apps/user-web`（Vue3）+ `apps/admin-web` | `apps/web`（Vue3，单前端） |
| 数据库 | MySQL（core/automation 共享实例）+ PostgreSQL（crawler） | MySQL（apps/api）+ crawler 内部存储 |
| 鉴权 | 前端 → Java 网关（verify_internal_token）→ Python | 前端直连 Python（verify_internal_or_current_user） |

**同步方式结论**：开源版前端页面（`apps/web`）与商业版 `apps/user-web` 同构，多数页面/组件已同步过（部分逐字节一致）；主要差异在后端（开源版无 Java 层，需在 Python 侧补齐逻辑）与少量前端断点。所有新增路由必须沿用开源版鉴权方式（`verify_internal_or_current_user`），不得复制商业版的 `verify_internal_token` 模式。

### A2. 实施步骤（按顺序执行）

#### A2.1 数据库迁移（新增 2 个迁移脚本）

**迁移 1：`xianyu_goods` 增加 can_edit / edit_note 列**

参照商业版 `apps/automation-service/migrations/V1.21__add_fish_shop_goods_edit_capability.sql`（第 7-10 行）。

在开源版 `apps/api/migrations/` 新增（版本号取当前最大号+1，例如 `045`，实际按 `README.md` 中的编号规则确认）：

```sql
ALTER TABLE xianyu_goods
  ADD COLUMN can_edit TINYINT NOT NULL DEFAULT 1 COMMENT '商品是否可编辑(鱼小铺itemEdit)', 
  ADD COLUMN edit_note VARCHAR(255) DEFAULT NULL COMMENT '不可编辑原因';
```

> 幂等性：`ALTER TABLE ... ADD COLUMN` 在 MySQL 无 `IF NOT EXISTS`，需按项目既有惯例（如 `005_runtime_schema_compatibility.sql` 用 information_schema 判断）包一层存在性检查。

**迁移 2：新增编辑快照表 `xianyu_goods_edit_snapshot`**

```sql
CREATE TABLE IF NOT EXISTS xianyu_goods_edit_snapshot (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  tenant_id BIGINT NOT NULL DEFAULT 0,
  account_id BIGINT NOT NULL,
  external_goods_id VARCHAR(64) NOT NULL,
  snapshot_json JSON NOT NULL,
  source VARCHAR(20) NOT NULL DEFAULT 'edit',
  account_type VARCHAR(20) NOT NULL DEFAULT 'fish_shop',
  created_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_snapshot_account_goods (account_id, external_goods_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

同步在 `apps/api/app/models/entities.py` 增加 ORM 模型 `XianyuGoodsEditSnapshot`（参照商业版 automation-service `entities.py:917-929`）。
