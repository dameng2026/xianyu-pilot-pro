# 通用模型按用户等级定价 - 设计文档

> 创建日期：2026-07-27
> 状态：已确认，待实现

## 一、问题背景

### 1.1 现状缺陷

后台存在两处费用配置入口，互相冲突导致无法精准设置价格：

| 配置位置 | 文件 | 字段含义 |
|---------|------|---------|
| 模型配置 → 通用模型 | `apps/admin-web/src/views/admin/model-config/index.vue` | `perCallPrice`（元/次）× `tokenExchangeRate`（默认100） |
| 独立费用设置 | `apps/admin-web/src/views/admin/ai-pricing/index.vue` | `tokensPerCall`（固定售价 Token） / `costPerCall`（成本） |

两处都写入同一张表 `ai_model_price_config`，但后端 `AiBillingService.estimateUsage()` 的优先级是：
1. 若 `tokensPerCall > 0` → 走固定售价模式
2. 否则走 `perCallPrice × tokenExchangeRate` 公式

哪个生效取决于另一个是否 > 0，管理员无法直观判断用户实际扣费。

### 1.2 场景化定价无效

`ai_scene_sell_config` 表为通用模型不同 scene（`workflow_rewrite` / `opportunity_rewrite` 等）分别记录价格，但通用模型已强制按次计费，这些场景价实际无效，造成配置冗余。

### 1.3 缺乏等级维度

现有表只有"模块维度"，没有"用户等级维度"，无法实现 VIP/SVIP 差异化定价。

## 二、设计目标

1. **统一入口**：将通用模型价格配置统一到「费用设置」页（`ai-pricing/index.vue`），从「模型配置」页移除价格字段
2. **按等级定价**：通用模型按用户等级（normal/vip/svp）分别配置扣费 Token 数
3. **简化字段**：通用模型 section 移除无效的按 Token 计费字段（inputPricePer1k 等）
4. **保留规则**：通用模型仍强制按次计费、前端不硬编码、调用前校验余额

## 三、技术方案

### 3.1 数据库改动

#### 新增表 `ai_model_tier_price`

迁移脚本：`apps/core-api/src/main/resources/db/migration/V1.18__create_ai_model_tier_price.sql`

```sql
CREATE TABLE IF NOT EXISTS ai_model_tier_price (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  module_key VARCHAR(64) NOT NULL,
  user_level VARCHAR(16) NOT NULL,
  tokens_per_call BIGINT NOT NULL DEFAULT 3,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_module_level (module_key, user_level)
);

-- 迁移现有 tokensPerCall 到三档（默认 3 Token）
INSERT INTO ai_model_tier_price (module_key, user_level, tokens_per_call)
SELECT 'model-config-general', 'normal', COALESCE(tokens_per_call, 3)
FROM ai_model_price_config
WHERE module_key = 'model-config-general'
ON DUPLICATE KEY UPDATE tokens_per_call = tokens_per_call;

INSERT INTO ai_model_tier_price (module_key, user_level, tokens_per_call)
SELECT 'model-config-general', 'vip', COALESCE(tokens_per_call, 3)
FROM ai_model_price_config
WHERE module_key = 'model-config-general'
ON DUPLICATE KEY UPDATE tokens_per_call = tokens_per_call;

INSERT INTO ai_model_tier_price (module_key, user_level, tokens_per_call)
SELECT 'model-config-general', 'svp', COALESCE(tokens_per_call, 3)
FROM ai_model_price_config
WHERE module_key = 'model-config-general'
ON DUPLICATE KEY UPDATE tokens_per_call = tokens_per_call;
```

- 仅追加新表，不修改 `ai_model_price_config` 表结构（其他模型仍用此表）
- 迁移脚本幂等（`IF NOT EXISTS` + `ON DUPLICATE KEY UPDATE`）
- 现有 `tokensPerCall` 值会被迁移到三档，初始都为 3，管理员后续调整为 VIP=2、SVIP=1

#### 同步迁移清单

`db/migrations-manifest.json` 中 core-api 数组追加 V1.18 条目，填入正确 sha256。

### 3.2 后端改动

**文件**：`apps/core-api/src/main/java/com/xianyu/admin/service/AiBillingService.java`

#### `estimateUsage()` 改造

```java
// 通用模型（model-config-general）按用户等级查 ai_model_tier_price
if ("model-config-general".equals(price.get("module_key"))) {
    billingMode = "per_call";
    Long userId = currentUser();
    String userLevel = userLevelRepository.findById(userId)
        .map(User::getUserLevel).orElse("normal");
    Long tierTokens = tierPriceRepository
        .findTokensByModuleAndLevel("model-config-general", userLevel);
    chargeTokens = tierTokens != null ? tierTokens : 3L;
    // 不再走 perCallPrice × tokenExchangeRate 公式
}
```

#### `/ai-billing/balance` 接口

返回的 `perCallTokens` 改为按当前用户等级查 `ai_model_tier_price`：

```java
// 原来：perCallTokens = perCallPrice × tokenExchangeRate = 3
// 改为：perCallTokens = tierPriceRepository.findTokensByModuleAndLevel(...)
```

#### 新增接口

**`GET /api/ai-pricing/tier-config?moduleKey=model-config-general`**

返回：`{ normal: 3, vip: 2, svp: 1 }`

**`PUT /api/ai-pricing/tier-config`**

请求体：
```json
{
  "moduleKey": "model-config-general",
  "normal": 3,
  "vip": 2,
  "svp": 1
}
```

#### 新增 Repository / DTO

- `AiModelTierPriceRepository extends JpaRepository<AiModelTierPrice, Long>`
- 实体 `AiModelTierPrice.java`
- DTO `TierPriceConfigDTO.java`

### 3.3 管理端改动

#### `apps/admin-web/src/views/admin/ai-pricing/index.vue`

通用模型 section 简化为：

```
通用模型按次计费配置
├─ 每次扣费 Token 数（按用户等级）：
│   普通用户 [3]    VIP [2]    SVIP [1]    （三档并排同一行）
└─ 上游成本记录（仅参考，不影响扣费）
```

**移除字段**：`tokensPerCall`（单值）、`perCallPrice`、`tokenExchangeRate`、`inputPricePer1k`、`outputPricePer1k`、`cachedInputPricePer1k`、`minChargeToken`、`billingMode`、`billingUnit`

**保留字段**：`costPerCall`（成本记录，仅供管理员查看盈亏）

#### `apps/admin-web/src/views/admin/model-config/index.vue`

通用模型 section 移除：`perCallPrice`、`tokenExchangeRate`
保留：`providerName`、`baseUrl`、`apiKey`、`defaultModel`、`requestTimeout`、`enabled`、`polishKeywords`、`polishForbiddenKeywords`
新增提示：「价格配置请前往 费用设置 页面」

### 3.4 前台改动

**无需改动**。

- `aiTokenGuard.js` 调用 `/ai-billing/balance`，后端返回的 `perCallTokens` 改为按等级查表
- 充值弹窗与 AiCsPanel 的扣费显示自动反映正确价格

### 3.5 数据流

```
管理端配置
  ai-pricing/index.vue (三档并排输入)
    → PUT /api/ai-pricing/tier-config
    → 写入 ai_model_tier_price 表

用户前台调用
  ensureAiTokenBalance()
    → GET /ai-billing/balance
    → 后端读取 sys_user.user_level
    → 查 ai_model_tier_price WHERE module_key=? AND user_level=?
    → 返回 { balance, perCallTokens: <等级对应值> }

  调用 AI 接口
    → AiBillingService.estimateUsage()
    → 同样按等级查表
    → chargeTokens = tier tokens_per_call
    → AiBillingService.charge() 扣费
```

## 四、关键约束保留

1. ✅ 通用模型仍强制按次计费（`billingMode = per_call` 逻辑保留）
2. ✅ 前端不硬编码扣费数（继续从后端读取 `perCallTokens`）
3. ✅ 调用前校验余额
4. ✅ 余额不足返回 402 阻断

## 五、迁移安全性

- 仅新增表，不修改 `ai_model_price_config` 表结构（其他模型仍用此表）
- 迁移脚本幂等（`CREATE TABLE IF NOT EXISTS`、`ON DUPLICATE KEY UPDATE`）
- 用户等级未配置时默认 `normal`，不会出现查不到价格的情况
- 上线前按 `database-migration-on-release.md` 规则备份数据库、产出 evidence

## 八、测试要点

1. **迁移幂等性**：连续执行两次 V1.18 脚本不报错
2. **数据迁移正确**：现有 `tokensPerCall=3` 被正确迁移到 normal/vip/svp 三档
3. **未配置等级默认值**：`user_level` 为空或未知值时，默认按 normal 等级计费
4. **三档扣费正确**：normal 扣 3、vip 扣 2、svp 扣 1
5. **前台余额显示正确**：不同等级用户登录前台，余额接口返回对应的 `perCallTokens`
6. **管理端配置生效**：修改三档价格后，下次调用立即按新值扣费
