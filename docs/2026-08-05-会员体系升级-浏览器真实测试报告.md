## 三、本次测试发现并修复的问题

### 1. 添加账号 500：`snapshot_time` 无默认值（存量 bug，阻断所有账号新增）

现象：通过 API 手动添加账号时，Java 后端返回 500“账号保存失败，数据库异常”。

根因：`xianyu_account_health_snapshot.snapshot_time` 为 `NOT NULL` 且无默认值，`XianyuAccountHealthSnapshotMapper.insert` 未写入该字段，导致新增账号（含扫码/手动）整体失败。

修复：
- `XianyuAccountHealthSnapshotMapper`：INSERT 补充 `snapshot_time`（与 `collected_time` 同值）。
- `SchemaCompatibilityRunner`：建表语句补充 `snapshot_time DATETIME DEFAULT CURRENT_TIMESTAMP`，并对存量表执行幂等 `ALTER ... SET DEFAULT (CURRENT_TIMESTAMP)`。

复测：普通/VIP/SVIP 手动添加均正常；超限拦截与新增成功均符合预期。

### 2. 移动端“添加账号”拦截时机滞后（本次改造引入的体验缺口）

现象：移动端普通用户点“添加账号”先打开“扫码登录 / 手动 Cookie”选择面板，选择具体方式后才弹升级引导。

修复：主“添加账号”按钮改为 `onAddAccountClick()`，先调用 `ensureCanAddStore()`，未超限才打开选择面板。

复测：普通用户点击“添加账号”立即弹出升级引导确认框；VIP 用户正常打开选择面板。

### 3. 个人中心“你的等级”标识固定显示在 SVIP 列（存量 UX 问题）

现象：无论当前用户等级，功能对比表 SVIP 列都显示“你的等级”，信息不准确。

修复：按 `overview.activePlan.planCode` 计算当前等级列，标识显示在对应列（普通用户 / VIP 单店版 / VIP / SVIP）。

复测：普通用户登录后，“你的等级”显示在“普通用户”列。

## 四、环境性/历史问题（非本次改造引入，已记录）

1. admin-web 首次启动会话出现 Vite “Outdated Optimize Dep” 504，导致用户管理模块首屏加载失败；重启 dev server 并新开浏览器会话后正常。属本地开发环境依赖缓存问题，与业务代码无关。
2. 前台 SSE 在 Vite dev 代理下返回 `text/plain`，浏览器控制台报 EventSource MIME 错误；生产环境由 Nginx 正确返回 `text/event-stream`，不影响业务。
3. 首页轮播图未配置时请求图片 404（后台未配置内容）。
4. 后台“数据管理”路由缺少组件（ComponentLoader 报错），为既有未实现模块。
5. 本地仓库 HEAD 上 `FeatureSwitchServiceTest` 2 个用例与 `XianyuAccountServiceTest` 1 个用例本就失败（已用临时 worktree 对照确认），与本次改动无关。
